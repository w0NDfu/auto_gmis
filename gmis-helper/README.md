# GMIS 报名助手 · 本机多账号后台 0.5.0

最新 build：`sso-bound-captcha-20261021`，启动标题为「验证码步骤保留修复版（持续挂机）」。任务和定时器由本机后台执行，验证码在后台本地识别，不依赖控制台保活或页面定时器。

本次修复统一认证出现图形验证码后被表单恢复逻辑重开登录页的问题：已要求验证码时直接保留当前认证步骤，支持账号密码框暂时隐藏或禁用的补充验证码表单；按所属表单定位确认按钮，识别学校 `code-img` 的 Blob 图片，并继续核对图片与表单绑定。验证码未就绪时给出明确提示，不再无验证码重复提交。自动化适配器回归覆盖「首次提交要求验证码 → 读取当前图片 → 填写验证码 → 再次提交 → 进入门户」；未使用真实账号提交登录。

此修复兼容 **0.5.0 扩展**，只需更新本机后台文件、关闭旧后台再运行启动脚本，并重新配对。下方跨大版本升级说明仍适用于旧于 0.5.0 的扩展。

## 使用

需要 Google Chrome 和 Node.js 20+。同时更新配套扩展到 **0.5.0**，重新加载扩展、关闭旧控制台再打开；关闭旧后台后运行 `start-helper.cmd`，重新配对。启动脚本检测 Playwright Core 与 Tesseract.js，缺少依赖时执行 `npm ci --ignore-scripts --registry=https://registry.npmjs.org`。

在扩展内添加账号、选择多个项目并启动。看到后台接管日志后，控制台可以关闭；再次连接同一后台可查看并停止任务。**请保持电脑开机且不休眠、本窗口开启。** 关闭后台、电脑重启会清除内存中的账号和任务，不自动恢复。

## 持续挂机

- 设定时间前一直等待，等待和定时校验不扣尝试次数；没有固定挂机时长上限。
- 任务按账号隔离；每个项目独立计时，同账号轮流尝试。成功项目退出后继续其他项目，全部成功或每账号尝试额度用完后结束。
- 查询暂时失败时持续等网络恢复，登录会话过期时自动尝试重新登录。真实二次认证、权限变化、报名截止或未知提交结果会明确结束或提示处理，不能强行忽略。
- 手动停止立即撤销任务的写入权限；已经发出的报名请求仍需核验。关闭控制台不等于停止，关闭后台会停止全部。
- 所有报名只在成功报名列表按活动编号核验后报告成功；提交不明时不盲目重复提交。

## 数据与依赖

后台仅绑定 `127.0.0.1:8767`，随机配对码经 Bearer 头认证，校验 Origin 和 Host。账号密码、Cookie、配对码、任务和最多 500 条任务日志只保存在内存；不上传到第三方服务。

依赖锁定为 `playwright-core@1.64.1` 与 `tesseract.js@6.0.1`。使用本机 Chrome，无额外浏览器下载。Node OCR 读取本地英文模型，复用各账号隔离页面完成图片预处理，识别队列按序执行；不会读取普通 Chrome 配置中的会话。

源码开发环境从相邻 `gmis-extension` 使用共享任务引擎和识别模型；独立后台 ZIP 内包含 `task-runtime/` 和 `ocr-data/`，无须另拷源码。新依赖首次安装需要联网，任务运行时识别模型本地加载。

开发验证：`npm test`。测试使用模拟账号和学校接口，不实际登录或报名。`python package_helper.py` 打包源码、共享引擎及识别模型，不包含 node_modules、截图、运行数据和秘密。
