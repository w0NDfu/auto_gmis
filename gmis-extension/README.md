# GMIS 报名助手 0.5.0

Chrome 控制台管理多个独立账号，本机 Node.js 后台负责等待、验证码识别、报名和结果核验。选择劳动实践、学术报告的多个项目后，可以持续挂机。

## 升级与使用

1. 同时更新扩展和后台。停止旧任务，在 Chrome 扩展管理页重新加载 `gmis-extension`，关闭旧控制台并重新打开；页面版本应为 **0.5.0**。
2. 关闭旧后台，双击 `gmis-helper/start-helper.cmd`；标题应为 **持续挂机版**。需要 Google Chrome 和 Node.js 20+。首次启动或缺少 OCR 依赖时从官方 npm 安装锁定版本依赖。
3. 复制后台窗口的配对码到控制台，连接后在「自动登录设置」添加学号、密码。默认走统一身份认证 → 校园门户 → 研究生系统，并核对主页实际学号。旧 GMIS 独立登录入口保留供需要的用户选择。
4. 获取项目列表，勾选一个或多个项目。可跨劳动实践、学术报告两类选择，关键词支持部分名称、空格分隔多个词，切换筛选不会清除选择。
5. 填写开始尝试时间、重试间隔及每账号最多尝试次数，点击「启动勾选账号」。看到「后台挂机任务已接管」后，任务已交给本机后台。
6. **控制台可以关闭，后台任务继续。** 重新打开控制台并用同一后台的配对码连接，可以恢复任务状态、已选项目和最近日志。停止任务请使用停止按钮，或关闭本机后台窗口。

电脑须保持开机、不休眠，网络和本机后台窗口须保持运行。账号、凭据、任务都仅存在内存；关闭后台或重启电脑会停止并清除任务，不会开机自动恢复。

## 挂机与停止条件

- 没有固定的挂机时长上限。设定尝试时间前一直等待，**等待不扣次数**；默认按各项目报名开始时间提前 1 分钟开始尝试，也可输入完整北京时间。
- 每账号全部项目共用 1–99999 次尝试额度，默认 90。成功项目退出，其他项目继续；全部成功或额度用完时结束。两类列表最多两个并发读取，同账号的验证码、提交和核验依次执行，不同账号并行。
- 失败后等待 0.01–60 秒；0.01 秒不包含网络、验证码识别和核验耗时。到尝试时间后即使服务器尚未开放，也会按设置尝试并消耗额度。
- 「满额后继续重试」默认开启；取消勾选时满额项目单独结束。学校取消项目或报名截止后结束该项目，仍可继续其他项目。
- 查询接口暂时失败时后台等待网络恢复，不因控制台断开而结束。学校登录过期时尝试自动重新登录；真正的短信、滑块或其他二次认证会明确提示需处理。
- 提交超时、返回含义不明时先查询成功报名列表，不盲目重复提交；仍无法确认时停止该账号并提示核验。不能保证抢到名额。

## 运行方式

0.5.0 将任务、定时器和本地 OCR 全部迁到本机后台；旧版 45/180 秒控制台续租机制不再用于这些后台任务。控制台只负责配置、查看和显式停止，关闭或刷新它不会终止后台任务。

数字图形验证码使用锁定版本 Tesseract.js 6.0.1，由后台现有的账号隔离页面预处理后送到 Node.js 识别线程。识别模型本地加载，运行时不上传验证码到外部服务。

后台仅监听 `127.0.0.1:8767`，配对码通过 Authorization 请求头发送。凭据和 Cookie 不写磁盘；项目日志不包含密码或验证码。第三方资源见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

## 开发

`npm test` 运行模拟测试。`python package_extension.py` 校验 OCR 资产并生成扩展 ZIP；相邻后台的 `python package_helper.py` 生成含共享任务引擎和本地识别模型的后台 ZIP。实际登录和报名结果需在学校系统核验。
