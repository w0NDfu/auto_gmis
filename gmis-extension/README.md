# 北化报名助手 0.4.1

同一个 Chrome、同一个扩展控制台添加多个学校账号，并行执行劳动实践或学术报告报名。**无需为各账号创建 Chrome 配置。** 每个账号由本机后台分配独立的内存浏览器会话，Cookie 和验证码互相隔离。

## 开始使用

1. 停止旧任务。在 Chrome 扩展管理页重新加载 `你的解压目录\auto_gmis\gmis-extension`，关闭旧控制台，再点击扩展图标。新版页面标题应为「多个账号，一个控制台」，版本 **0.4.1**。同时关闭旧后台并重新运行启动脚本；旧进程不会自动加载新代码。
2. 双击相邻目录 `你的解压目录\auto_gmis\gmis-helper\start-helper.cmd`。需要 Node.js 20+ 和已安装的 Google Chrome。依赖已在本工作区安装；重新解压的后台首次启动会执行 `npm ci` 安装锁定版本依赖，无需下载额外浏览器。
3. 复制后台窗口里的配对码，在控制台粘贴并连接。后台只监听 `127.0.0.1:8767`，不开放给其他电脑。
4. 在「自动登录设置」保留默认 **统一身份认证（i 北化）**，逐个输入备注、学号和 **sidportal.buct.edu.cn 的统一身份认证密码**，点击「添加并自动登录」。后台按 `sidportal 登录 → i 北化 → 研究生系统（/oauthLogin/bjhgdx）→ GMIS 主页学号核验` 建立该账号的会话。无需填写旧 GMIS 独立入口的密码；该方式仍保留在下拉菜单中供明确需要的人选择。
5. 勾选账号，选择「劳动实践」或「学术报告」，输入项目名称的一部分，点击「为勾选账号匹配项目」。恰好匹配一个项目时自动选中；匹配多个时点击相应账号并手动选定。
6. 设置时间与重试参数，点击「启动勾选账号」。各账号分别查询、识别验证码、提交并核验。可以停止当前账号或停止全部。

## 时间与重试

0.4.1 修复「统一认证页面未出现可识别的账号密码表单」：已在学校真实页面确认默认标签为「企业微信扫码」，需切换到「用户名密码」，实际登录按钮为 `#submitBtn`「立即登录」。新版优先通过 tab 角色切换并识别此按钮，随后匹配 `#nameInput` 用户名框和可见密码框，不读取隐藏的同名表单字段。已通过浏览器工具在真实页运行新版表单识别/切换方法验证成功，未填写密码或提交登录。

后台核验追加修复：GMIS 主页的学号由 `getxscardinfo` 异步加载，新版等待有效学号最多 15 秒，避免空值被误报为「登录学号核验不一致」。超时会提示「学号仍未加载」；真实不一致仍停止，并给出遮盖后的配置学号和实际学号。此项只修改后台，使用现有 0.4.1 扩展时无需重新加载扩展，重启后台、用新配对码重新连接并添加账号即可。

登录分步诊断版后台修复了隐式导航等待和按输入框序号定位的脆弱行为。重启后后台标题应显示「登录分步诊断版」，窗口会逐步显示填写、提交、进入研究生系统、加载主页和核验学号的过程。失败会返回具体步骤、耗时和去除查询参数的页面路径，不再显示笼统的「后台操作失败，请检查 Chrome 是否已安装、学校网络是否可用」。无需重新加载现有 0.4.1 扩展；旧日志本身无法确定当时的具体失败步骤。

0.4.0 修正了登录入口：默认使用你指定的 [统一认证页面](https://sidportal.buct.edu.cn/login?service=https:%2F%2Fi.buct.edu.cn%2F)。i 北化的「研究生系统」链接由浏览器只读检查确认指向 GMIS `/oauthLogin/bjhgdx`；后台在同一隔离会话打开此入口并完成重定向，不把 i 北化登录成功单独视为 GMIS 已登录。账号密码通过学校原生表单填写，沿用学校页面的加密和 CSRF 处理，不硬编码认证票据。

登录页没有验证码时直接填写账号密码，不额外请求 GMIS 独立入口的验证码；出现四位数字图形码时由本地 OCR 识别并核对图片。若学校要求滑块、短信、扫码或其他二次验证，会给出明确提示并停止，不把它们当作普通数字图形码提交。真实账号的自动统一认证登录尚未实测。

- 开始尝试时间留空：每个项目按学校返回的**报名开始时间提前 1 分钟**开始；也可填写完整日期时间，按北京时间解释。
- 重试间隔允许 **0.01–60 秒**，界面默认 0.01 秒，最多尝试次数默认 90，可填 1–99999。
- 间隔指一次失败后到下一次尝试之间的等待时间。网络、身份检查、验证码识别和结果核验另需耗时，因此不代表每秒提交 100 次。同一账号不会重叠提交，多个账号可并行。
- 尝试次数也会消耗在报名未开放、预检未放行或验证码不确定的情况。很早开始、间隔很短时可能提前用尽次数，请结合自己的开始时间和次数设置。
- 满额默认停止，勾选「满额后继续重试」可等待释放名额。
- 成功、截止或次数用尽时停止。提交超时或结果不明确时先查成功报名列表，无法确认则停止重发，避免重复提交。

以上批量设置作用于本次启动的勾选账号；不同批次可以选择不同类别、项目和尝试时间。运行中的任务保留启动时的参数。

## 会话与数据

账号密码、配对码、账号会话、任务和日志均保存在进程/页面内存，不写入扩展存储或文件；退出后台后清除账号和 Cookie。配对码每次启动重新生成。关闭后重新使用需要重新添加账号；仅刷新控制台可以重新配对找回后台仍保留的账号，但不会自动恢复报名任务。每个账号同时隔离 sidportal、i 北化和 GMIS 的 Cookie，避免不同网站各自已有的登录账号混用。

保持后台窗口和控制台打开。控制台关闭会请求停止；若异常断开，后台在任务租约过期后拒绝新的验证码/提交请求。已经传到学校的请求无法撤回。后台使用安装的 Chrome 无界面运行，各账号是独立内存 Context，与你正在使用的 Chrome 标签页不共享学校登录状态。

所有学校地址由后台固定白名单限定；本机服务需配对认证，仅允许扩展 Origin。验证码图片只在本机 OCR 处理；账号密码会通过学校 HTTPS 登录页面发送给学校。

```powershell
cd 你的解压目录\auto_gmis\gmis-extension
npm test
python package_extension.py
cd ..\gmis-helper
npm test
python package_helper.py
```

离线测试覆盖独立会话、并发队列、停止/租约、接口白名单、配对认证、0.01 秒重试、自动登录读取重试、提交不盲重发和结果核验。界面可通过 `multi.html?preview=1` 在本地 HTTP 服务中预览，使用虚构数据，不连接学校。**尚未使用真实多账号、真实验证码和实际报名验证新版流程**。
