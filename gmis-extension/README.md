# GMIS 报名助手 0.4.3

## 后台续租修复（0.4.3）

旧版由控制台页面每 10 秒续租，后台租约仅 45 秒。控制台隐藏后定时器延迟、短暂连接失败或系统暂停，可能导致任务租约失效；旧日志又统一写成「后台连接中断」，无法判断具体原因。

新版由扩展 Service Worker 每 10 秒独立续租，通过仅限本扩展控制台的长连接消息维持活动；不再依赖页面定时器。租约放宽至 180 秒，连续运行期间最多容忍两次临时连接失败；明确的停止、租约过期、配对拒绝或消息通道断开立即停止，不自动重建旧任务。关闭控制台或点击停止会撤销后台租约；凭据和配对码仍仅在内存中。

**本次必须同时升级扩展和后台至 0.4.3**：停止旧任务、重新加载扩展、关闭旧控制台再打开；关闭并重新运行后台后重新配对。后台标题应为「后台续租修复版」。模拟测试覆盖无页面定时器的 30 分钟续租、短暂故障恢复、通道关闭和过期任务不复活；未使用真实学校账号报名。

## 多选项目与并发查询（0.4.2）

选择「全部：劳动实践 + 学术报告」，获取列表后可同时勾选两类的多个项目。「已选项目」显示完整选择，切换类别、账号或关键词不会覆盖选择。每个账号分别选择自己的项目；同类同名的多个候选不会被模糊匹配自动全部选中。

每个账号最多并发两个列表查询；同一类别同时发生的相同查询共用在途请求，结果核验不缓存。每个项目独立按报名开始前 1 分钟或自定义时间启动等待，到点的项目轮流执行完整验证码、报名、核验流程。未到尝试时间的项目不会挡住其他项目。不同账号可并行，OCR 引擎仍共用队列。**最多尝试次数是该账号全部项目合计的上限**，成功项目不再重试；满额（未勾选继续）、截止或消失只停止相应项目；未知提交结果或登录失效停止整个账号，防止后续任务干扰待核验结果。运行中登录失效后需要重新登录并启动；不会在另一个项目的验证码期间自动更换登录会话。

升级需要同时更新扩展和本机后台：停止任务、重新加载扩展、关闭旧控制台并重新打开；关闭旧后台后运行 `start-helper.cmd`，重新配对。界面与后台版本均为 **0.4.3**。并发查询能缩短串行读取耗时，实际报名速度仍取决于学校响应与验证码识别，不能保证抢到名额。

同一个 Chrome、同一个扩展控制台添加多个学校账号，并行执行劳动实践或学术报告报名。**无需为各账号创建 Chrome 配置。** 每个账号由本机后台分配独立的内存浏览器会话，Cookie 和验证码互相隔离。

## 开始使用

1. 停止旧任务。在 Chrome 扩展管理页重新加载 `你的解压目录\auto_gmis\gmis-extension`，关闭旧控制台，再点击扩展图标。新版页面标题应为「多个账号，一个控制台」，版本 **0.4.3**。同时关闭旧后台并重新运行启动脚本；旧进程不会自动加载新代码。
2. 双击相邻目录 `你的解压目录\auto_gmis\gmis-helper\start-helper.cmd`。需要 Node.js 20+ 和已安装的 Google Chrome。依赖已在本工作区安装；重新解压的后台首次启动会执行 `npm ci` 安装锁定版本依赖，无需下载额外浏览器。
3. 复制后台窗口里的配对码，在控制台粘贴并连接。后台只监听 `127.0.0.1:8767`，不开放给其他电脑。
4. 在「自动登录设置」保留默认 **统一身份认证（校园门户）**，逐个输入备注、学号和 **sidportal.buct.edu.cn 的统一身份认证密码**，点击「添加并自动登录」。后台按 `sidportal 登录 → 校园门户 → 研究生系统（/oauthLogin/bjhgdx）→ GMIS 主页学号核验` 建立该账号的会话。无需填写旧 GMIS 独立入口的密码；该方式仍保留在下拉菜单中供明确需要的人选择。
5. 勾选账号，选择「全部」或某一类别，输入项目名称的一部分，点击「为勾选账号匹配项目」。恰好匹配一个项目时加入选择；匹配多个时点击相应账号并手动勾选。可重复获取并选择多个项目，已有选择保留。
6. 设置时间与重试参数，点击「启动勾选账号」。各账号分别查询、识别验证码、提交并核验。可以停止当前账号或停止全部。

## 时间与重试

0.4.1 修复「统一认证页面未出现可识别的账号密码表单」：已在学校真实页面确认默认标签为「企业微信扫码」，需切换到「用户名密码」，实际登录按钮为 `#submitBtn`「立即登录」。新版优先通过 tab 角色切换并识别此按钮，随后匹配 `#nameInput` 用户名框和可见密码框，不读取隐藏的同名表单字段。已通过浏览器工具在真实页运行新版表单识别/切换方法验证成功，未填写密码或提交登录。

后台核验追加修复：GMIS 主页的学号由 `getxscardinfo` 异步加载，新版等待有效学号最多 15 秒，避免空值被误报为「登录学号核验不一致」。超时会提示「学号仍未加载」；真实不一致仍停止，并给出遮盖后的配置学号和实际学号。此项只修改后台，使用现有 0.4.1 扩展时无需重新加载扩展，重启后台、用新配对码重新连接并添加账号即可。

登录分步诊断版后台修复了隐式导航等待和按输入框序号定位的脆弱行为。重启后后台标题应显示「登录分步诊断版」，窗口会逐步显示填写、提交、进入研究生系统、加载主页和核验学号的过程。失败会返回具体步骤、耗时和去除查询参数的页面路径，不再显示笼统的「后台操作失败，请检查 Chrome 是否已安装、学校网络是否可用」。无需重新加载现有 0.4.1 扩展；旧日志本身无法确定当时的具体失败步骤。

0.4.0 修正了登录入口：默认使用你指定的 [统一认证页面](https://sidportal.buct.edu.cn/login?service=https:%2F%2Fi.buct.edu.cn%2F)。校园门户的「研究生系统」链接由浏览器只读检查确认指向 GMIS `/oauthLogin/bjhgdx`；后台在同一隔离会话打开此入口并完成重定向，不把 校园门户登录成功单独视为 GMIS 已登录。账号密码通过学校原生表单填写，沿用学校页面的加密和 CSRF 处理，不硬编码认证票据。

登录页没有验证码时直接填写账号密码，不额外请求 GMIS 独立入口的验证码；出现四位数字图形码时由本地 OCR 识别并核对图片。若学校要求滑块、短信、扫码或其他二次验证，会给出明确提示并停止，不把它们当作普通数字图形码提交。真实账号的自动统一认证登录尚未实测。

- 开始尝试时间留空：每个项目按学校返回的**报名开始时间提前 1 分钟**开始；也可填写完整日期时间，按北京时间解释。
- 重试间隔允许 **0.01–60 秒**，界面默认 0.01 秒，最多尝试次数默认 90，可填 1–99999。
- 间隔指一次失败后到下一次尝试之间的等待时间。网络、身份检查、验证码识别和结果核验另需耗时，因此不代表每秒提交 100 次。同一账号不会重叠提交，多个账号可并行。
- 尝试次数也会消耗在报名未开放、预检未放行或验证码不确定的情况。很早开始、间隔很短时可能提前用尽次数，请结合自己的开始时间和次数设置。
- 满额默认停止，勾选「满额后继续重试」可等待释放名额。
- 成功、截止或次数用尽时停止。提交超时或结果不明确时先查成功报名列表，无法确认则停止重发，避免重复提交。

以上批量设置作用于本次启动的勾选账号；不同批次可以选择不同类别、项目和尝试时间。运行中的任务保留启动时的参数。

## 会话与数据

账号密码、配对码、账号会话、任务和日志均保存在进程/页面内存，不写入扩展存储或文件；退出后台后清除账号和 Cookie。配对码每次启动重新生成。关闭后重新使用需要重新添加账号；仅刷新控制台可以重新配对找回后台仍保留的账号，但不会自动恢复报名任务。每个账号同时隔离 sidportal、校园门户和 GMIS 的 Cookie，避免不同网站各自已有的登录账号混用。

保持后台窗口和控制台打开。控制台关闭会请求停止；若异常断开，后台在任务租约过期后拒绝新的验证码/提交请求。已经传到学校的请求无法撤回。后台使用安装的 Chrome 无界面运行，各账号是独立内存 Context，与你正在使用的 Chrome 标签页不共享学校登录状态。

所有学校地址由后台固定白名单限定；本机服务需配对认证，仅允许扩展 Origin。验证码图片只在本机 OCR 处理；账号密码会通过学校 HTTPS 登录页面发送给学校。
